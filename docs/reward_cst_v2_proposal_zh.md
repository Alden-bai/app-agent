以下为历史候选分析：

## 实际问题

核对 `runs/grpo_expanded_20261110_v3/training-offload/groups`，用户表格与 8 次真实更新一致：

- 64 条候选：44 条奖励 1、8 条 0.975、2 条 0.95、10 条 0。
- 54 条成功轨迹都没有 quality rubric 项，S 按现行规则为 1，因此这批数据里软要求权重没有作用。失败样本的 S/T 不计算，不能从其空列表推断 rubric 没有软要求。
- 8 次更新中有 6 次全部成功，只有过程扣分带来组内差异。现有 Judge 确认的问题包括重复发现/查询 schema、猜测 ID 后写入、使用错误参数和答复添加无依据的信息。
- 这些结论来自已保存的 Judge 记录，尚不等于独立人工核验了全部 44 条满分轨迹；不能仅凭奖励分布断言 Judge 偏松，更不能为了制造差异强行扣分。

核心问题是奖励和优势归一化共同作用。现行计算为：

\[
A_i=\frac{R_i-\bar R}{\sigma_R+10^{-6}}
\]

7 条奖励 1、1 条 0.975 时，该扣分候选的优势为 −2.645431；如果改成 0.95，其优势仍约 −2.645591。整体放大相同来源的分差，几乎会被标准差归一化抵消。旧配置中，这种只有轻微缺陷的组和成功/失败混合组，优势 RMS 都接近 1。

另有 5 个组（2、6、8、10、11）被 held。各组都有一条候选的 `reward_exclusion` 为 `trajectory_quality_unsettled:ValueError: api_context_limit_exceeded`。更新层统一记录成 `reward_admission_changed_or_missing`，掩盖了候选级根因。组 2、6、8、10 已有成功/失败混合结果；上下文错误导致整组不能参与，训练覆盖因此发生偏移。这不是全同分跳过，也不能把缺失奖励填成 0。

## 候选公式

保留两个 Judge 的职责、三个过程维度和证据约束。C 的定义不变：全部硬要求确认通过为 1；无明确硬失败、复核后仍有真实 unknown 为 0.3；有明确硬失败为 0。工具/API 故障、上下文超限、未完成取证不属于真实 unknown，仍为未结算。

\[
T=1-\frac{d_{\rm information}+d_{\rm feedback}+d_{\rm exploration}}3,
\quad d_k\in\{0,0.5,1\}
\]

\[
\boxed{R_{v2}=C[1-0.10(1-S)-0.30(1-T)]}
\]

S 仍由实际软要求组成，无软要求则为 1。软要求真实 unknown 的单项分仍为 0.3。不给失败添加部分完成分，不新增长度、token 或调用次数惩罚。

| 条件 | v1 | v2 候选 |
|---|---:|---:|
| 成功，软要求满足，无确认过程缺陷 | 1 | 1 |
| 成功，S=1，单维度轻微缺陷 | 0.975 | 0.95 |
| 成功，S=1，单维度明显缺陷 | 0.95 | 0.90 |
| 成功，S=0，三个维度均为明显缺陷 | 0.80 | 0.60 |
| 真实 unknown，S=T=1 | 0.30 | 0.30 |
| 真实 unknown，S=T=0 | 0.24 | 0.18 |
| 明确硬失败 | 0 | 0 |
| 评测故障/证据未结算 | null | null |

成功区间 [0.6, 1]，真实 unknown 区间 [0.18, 0.3]，失败为 0，因此仍满足单条轨迹的档位优先。此不等式不保证训练后成功率一定保持不变，成功率必须单独验证。

同时采用有标准差下限的优势计算：

\boxed{A_i=\frac{R_{v2,i}-\bar R_{v2}}{\max(\sigma_{R_{v2}},0.10)+10^{-6}}}
\]

0.10 是试验起点：小分差不再自动归一化到单位方差；标准差超过下限的组仍用原来的规则。全同分组仍为零优势，不注入随机分差。

这改变了优化规则，不能只改 `LAMBDA_T` 后称为相同方案。优势缩小的比例也不等于参数更新缩小的比例：当前训练每组进行一次 Adam 更新，优化器动量、自适应缩放和梯度裁剪都会影响效果。后续须报告实际梯度与更新，若仍需更强的跨任务权重控制，再单独实验多组累积；本轮不同时改动多个训练机制。

## 确认后的实施与重跑

1. 将确认的奖励与优势规则接入训练，使用新版本标识和新输出目录，保存参数及代码身份。旧运行、旧奖励和 checkpoint 不覆盖，旧准入不自动授权新策略。
2. 修复轨迹 Judge 的上下文打包：先去掉 `messages`、`latest_observation`、`chronological_steps` 之间的重复全文，保留每个动作当时可见的消息引用和完整证据；若仍超限，按实际模型预算分块取证、统一合并与去重。修复后重新校准，验证不会丢失前置观察或漏扣/重复扣分，仍未结算的整组继续 held。
3. 更新层透出候选级排除原因，分别统计评测故障、真实 unknown、全同分和有效更新，避免将它们混为一类。
4. 从本次相同的 SFT 起点开启新小规模试跑，先核对 8 次更新的奖励、优势、梯度及 Judge 有效率。8 次更新只能作为运行验证，不能证明质量改进。
5. 固定验证集，分别报告硬要求成功率、过程缺陷率、有效组比例及工具/token 成本；不能只看训练均值。软要求权重需要包含实际软要求的任务验证。更多任务覆盖和完整训练预算另行依据试跑结果确定。
